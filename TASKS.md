### Cellular data hardening / optimization

Discovered while validating `wata-metricsd` cellular field reads (2026-04-13). The modem hardware and SIM are fine — Swiss LTE coverage is excellent (Swisscom/Salt/Sunrise all `available, roaming, not-forbidden` on a network scan, RSSI -77 dBm on UMTS-900) — but the modem takes minutes-to-never to attach because of how it's configured.

**Root cause**: the modem's default `system-selection-preference` has acquisition order `cdma-1x, cdma-1xevdo, gsm, umts, lte, td-scdma` — **LTE is last**. The modem finds UMTS-900 first (Salt, MCC=228 MNC=03), gets `WCDMA Status: limited` because the SIM (Singtel, MCC=525 MNC=1) isn't allowed PS attach there, and parks on it without ever trying LTE. The CLAUDE.md hardware spec says "4G LTE data-only" but the actual config doesn't enforce that.

- [x] **Force LTE-only mode at cellular bringup** — `cell-data wake` now calls `ensure_lte_prefs` which idempotently applies `lte,automatic` if not already set. Acquisition order becomes `lte, umts, gsm, …` so LTE is tried first.
- [x] **Persist mode preference across modem resets** — verified: the QMI NAS preference is stored in modem NV and survives both `dms-set-operating-mode=reset` and full device reboots. `ensure_lte_prefs` is therefore a no-op after the first application. No oneshot service needed.
- [x] **Robust modem state-machine in `cell-data.sh`** — rewritten with a bounded 2-minute budget: `set_online` handles `online`/`low-power`/`offline`/`shutting-down`/`resetting` and escalates to `dms reset` + 10 s settle once on timeout. `do_wake` returns exit 1 for unreachable-online and exit 2 for PS-attach timeout, so callers (and `smoke-cellular`) can distinguish firmware deadlock from coverage/roaming problems.
- [x] **Roaming detection and logging** — `log_serving` records `plmn`, `rat`, `roaming` bool (MCC/MNC mismatch vs `nas-get-home-network`), home PLMN, and QMI's own roaming status to `/var/log/cellular.log` on every successful attach.
- [x] **`just smoke-cellular` end-to-end recipe** — runs `cell-data wake && up && ping -I ppp0 8.8.8.8 && down` against the live device. `just push-cell-data` scp's the current script in-place for quick iteration without a rootfs rebuild.
- [x] **Document the cellular bringup chain** — `docs/modem_data.md` now has a "Bringup chain (2026-04-13)" section with the sequence, expected prefs, recovery table, and smoke-test pointer.
- [x] **Approved roaming partners list — generated from authoritative source** — the runtime file `/etc/cellular/roaming-partners` is now auto-generated by `tools/gen-roaming-partners.py` (wired as `just gen-roaming-partners`), joining `eskimo_roaming.md` (manually extracted from https://www.eskimo.travel/en/network-coverage, 2026-04-13) against `tools/data/mcc-mnc-list.json` (vendored pbakondy/mcc-mnc-list, ~3000 operators). The script fuzzy-matches brand names, follows parent-brand aliases (Telefonica→Movistar/O2/Vivo, Veon→Beeline/Kyivstar, …), and caps multi-brand operators at 4 MCC/MNC rows to keep the file small. Current resolution: 118/139 Eskimo entries → 154 MCC/MNC pairs. 21 entries unresolved (small territories + brand-name gaps) — listed in script stderr output; fix individually by extending `BRAND_PARENTS`/`COUNTRY_ALIASES` and re-running. Home SIM is Eskimo (MVNO on Singtel IMSI 525-01). **Re-run after updating `eskimo_roaming.md`** — e.g. new partner relationships, or switching from Eskimo to a different eSIM provider; the script works unchanged as long as the new markdown uses the same `- Country\n  - Operator RAT` shape.
- [x] **LTE-only attach block — mitigated via UMTS fallback.** Commit 7df1869 switches `cell-data` RAT preference from `lte,automatic` to `lte|umts,automatic`, fixes the `ensure_rat_prefs` grep so it stops re-applying prefs every wake, and fixes `ensure_mcfg` `-A1→-A4` so the already-active Singtel MCFG isn't re-activated every wake (which was triggering a modem reset and dropping registration mid-flow). With those three fixes the modem attaches cleanly to Orange F / Sunrise / Salt on UMTS and stays attached across repeated `cell-data wake` cycles.
- [x] **PDP-activation reject cause identified — #33, Orange F Eskimo agreement is signalling-only.** Confirmed via direct AT on `/dev/smd7` (commit 4078320): on a clean UMTS attach to Orange F (serving PLMN `Orange F Eskimo`, 208/01), `AT+CGACT=1,1` returns `+CME ERROR: requested service option not subscribed` and `AT+CEER` confirms 3GPP 24.008 cause **#33 "requested service option not subscribed"**. So the previously-hypothesised "account is unfunded" was wrong: the account works, the network we keep attaching to just isn't on the data-roaming allowlist for this plan. Consequence: all firmware-patching scaffolding deleted — golden firmware is the only mode.
